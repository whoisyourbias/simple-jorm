# 07. 학습 페이지 구현 계획

작성일: 2026-11-03

> 최초 학습 페이지의 계획·검증 기록이다. 이후 페이지는 실제 데이터 접근 기술의 동작을 설명하도록 개편했다. 현재 페이지는 [학습 웹페이지](../../index.html), 개편 범위는 [단계별 핵심 기능 설계](10-stage-core-design.md)를 참고한다.

사용자 승인: 대화의 단계별 스토리형 단일 HTML 계획과 독립 리뷰 보완사항. Java·SQL 기초 독자, 오프라인 독립 HTML, 그림·코드·실행값 동시 강조, 실제 라이브러리와 구현 차이 명시.

## 작업

1. `doc/index.html`: 본문, JDBC/Mapper/트랜잭션/엔티티 CRUD/다음 단계, 생태계, 성능 부록과 공식·저장소 출처. CSS/JS/SVG 모두 내장.
2. 두 실행 실험실: Mapper 정상/어노테이션 누락/Object 처리와 송금의 외부 호출/자기 호출/바깥 트랜잭션 비교. 정지·재생·이전·다음·초기화·속도, 상태 복원 및 오래된 콜백 무효화.
3. 실제 차이: Spring JDBC의 조회·예외·타입 변환, MyBatis의 설정 분석/MapperMethod/SqlSession, Spring 트랜잭션 롤백 정책/전파/자기 호출, JPA 생명주기/flush와 자체 즉시 CRUD.
4. 반응형/접근성: 장면 핵심 한 문장, 값 추적 번호, 세로 모바일 그림, 코드 내부 스크롤, 현재 목차, 초점 유지, reduced-motion, no-JS 정적 순서.
5. README 두 곳에 HTML 링크 추가. Java 구현과 기존 변경사항 보존.

## 검증

- Node 기본 테스트로 실제 내장 플레이어 상태, 재생 종료, 시나리오 변경/초기화 후 지연 콜백, 속도, 예외 분기와 송금 결과를 검증한다.
- Chromium에서 file URL과 오프라인, 320/390/768/1024/1440 폭, 확대 대응, DOM 넘침/버튼/타이머/reduced-motion/no-JS, 콘솔 오류를 검사하고 대표 스크린샷을 직접 확인한다.
- 코드·공식 문서의 근거와 내부 앵커 및 링크를 검사한다. Java 변경이 없으므로 Gradle 테스트와 성능 벤치마크는 재실행하지 않는다.

## 실행 기록

- 기본 main은 origin/main과 동일(4a97101803756b08a0b91aeb454c16ca74bd0ae6). 기본 작업장의 EntityManagerFindTest 미커밋 변경은 복사/수정하지 않음.
- Codex 관리 worktree 및 codex/orm-learning-page 브랜치에서 작업. 관리 도구가 이동한 worktree 등록을 거절하므로 네이티브 경로를 유지함.
- node_repl 초기화가 OS 경로 오류로 실패. 설치된 Chrome과 Node 기본 WebSocket/CDP로 브라우저 검증(추가 의존성 없음).
- RED: 페이지 부재로 상태 검증 7개 실패를 확인함.
- 완료: 단일 HTML 본문, 두 애니메이션 실험실, README 진입 링크와 재실행 가능한 Node/Chrome 검증을 구현함.
- 가시성 수정: 모바일 상단 조작 버튼 추가(회귀검증 실패→통과), 앵커 오프셋 중복 제거(모바일 top251px→125px, 회귀검증 실패→통과).
- 최종 검증: Node 상태 테스트 7/7, Chrome 156 브라우저 검사 14/14, git diff --check 통과. Chrome 결과 JSON과 대표 스크린샷은 build/page-qa에 보관.
- 독립 최종 리뷰: 코드·공식 자료·실제 스크린샷 대조, 실질적 P1/P2/P3 지적 없음. Firefox/Safari/실물 모바일/스크린리더 실기는 미검증.
- Java 코드 변경이 없어 Gradle 테스트와 벤치마크는 실행하지 않음. 기본 작업장의 기존 수정은 보존함. 커밋·병합·배포는 수행하지 않음.
